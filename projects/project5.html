Canada Economy Intelligence Platform: Live StatCan Data, Tested and Self-Refreshing

The production-style project: a pipeline on Statistics Canada open data that checks for new releases every weekday, rebuilds a tested warehouse, re-runs honest forecasts, has an AI draft the monthly briefing, and redeploys the dashboard. No server, no cost, no manual steps.

The story

The other projects are built once and stay still. This one keeps running. Five StatCan tables (labour force, consumer prices, new housing prices, job vacancies, GDP) arrive as 1.4 GB of CSV, including one 1.18 GB file that DuckDB streams and filters instead of loading into memory. Versioned SQL turns them into raw, staging and mart layers, and every cleaning decision is logged with the rows it affected. A daily job asks StatCan whether anything changed, and rebuilds only when it did.

The theme is not claiming more than the data supports. A monthly job loss of 41,700 sounds like news, but it sits inside StatCan's own margin of error, so the chart shows it grey. Forecasts were judged by rules committed before any result: a seasonal model wins for next month's inflation, and for unemployment no model beats "next month equals this month", so that is what the site publishes. Gemini writes the monthly briefing, and code checks every number for the right value, the right measure and the right direction before anything goes live.

What the evaluation found

The first batch of 10 live Gemini briefings published only 5. Reading every failure showed most were my verifier's false alarms: in "a change of 0.00 and rose 1.4", it read "rose" as describing the 0.00. The fixes went in on both sides, every real failing sentence became a permanent test, and the next 20 runs all published a verified briefing. The 15 planted errors still had to be caught, so the verifier could not be loosened by accident.

Key decisions I'd defend in an interview

  • Months matched by calendar, not by row: StatCan suppresses small-group cells, which leaves gaps; LAG() would silently compare against the wrong month.
  • Robust anomaly scores: a classic z-score called the September 2020 unemployment drop normal, because COVID inflated the variance for three years. Median and MAD flag it at -6.7.
  • Significance before narrative: a forecast only "beats the baseline" with a Diebold-Mariano test, and a monthly move is only news when it beats StatCan's published standard error.
  • AI drafts, code verifies: a failed draft gets one retry with its exact failures listed, then a verified template is published. An API error never blocks the deploy.
  • Failure keeps the last good site: data tests run before export, so a bad StatCan release fails the job and the live page does not change.
