NL-to-SQL Agent: Asking the Churn Database Questions in Plain English

The follow-up to the churn project: instead of reading a dashboard, a club's director can type a question and get an answer, with the database query that produced it.

Gemini APIDuckDBAI safety Streamlitevaluation

What it does

You type a question like "which forwards at big clubs are most likely to leave?" and an AI (Google's Gemini) writes a database query to answer it. Every answer shows the query that ran and says in plain English what was worked out.

Making it safe to trust

AI-written queries go wrong in predictable ways: they refer to columns that don't exist, they do whatever text in the question tells them, and they quietly guess when a question is vague. So the AI only drafts the query, and code decides whether it runs. A query must be a single read-only question to the database. The database checks that every table and column it names really exists before anything runs, so a made-up column produces "couldn't verify this query" instead of a guess. And the connection itself is read-only, so even if every other check failed, nothing could be changed.

What testing found

3/3
attempts to trick it into ignoring its rules were refused
2/2
vague questions got a clarifying question instead of a silent guess
11/12
analysis questions answered correctly (the other asked a question it didn't need to)

The first version answered vague questions confidently. Asked for "risky" players, it picked its own definition of risky without saying so. I changed its instructions so it may choose how to present an answer but never how to define what was asked, and the next test run asked for clarification instead.

Why it's archived

It answered questions about game data. The same approach, tested much more thoroughly, now powers the Football Stats Agent on real match data.
