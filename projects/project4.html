NL→SQL Analyst Agent — Ask the Churn Database in Plain English

The continuation of Project 3: a sporting director can now just ask. An AI agent that writes and runs SQL — provably read-only, schema-grounded, and honest about uncertainty.

The story

Text-to-SQL is easy to demo and hard to trust: models hallucinate columns, run whatever they're told, and guess silently when questions are vague. This agent is the trust engineering. The LLM only ever drafts; code decides — five layers deep. A single-statement SELECT-only shape check, a keyword denylist, DuckDB's own EXPLAIN binding every table and column before execution (a hallucinated column returns "couldn't verify this query is safe," never a guess), and a read-only connection underneath, so even a total bypass cannot write. Every answer shows the SQL that actually ran plus a plain-English restatement of what was computed.

It's tested, not asserted: an 18-question eval — analytical, prompt-injection, ambiguous, and impossible questions — runs against the live agent with the full transcript committed. Getting the agent to ask for clarification instead of silently defining "risky" for you took a documented prompt iteration: v1 answered ambiguous questions confidently; v2's rule is that defaults may decide presentation, never definition.

Key decisions I'd defend in an interview

  • Read-only enforced in code, not prompting — a prompt is a request; code is a boundary. Injected text can steer what the model emits; it can't change what the validator returns.
  • DuckDB's EXPLAIN as the hallucination catcher — the database's own parser verifies every identifier, instead of half-reimplementing SQL with regex.
  • Built on Project 3's real database — the portfolio tells one story: pipeline → model → dashboard → self-serve agent, all on the same data.
