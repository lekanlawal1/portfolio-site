Football Stats Agent: Ask in English, Get an Answer You Can Check

Type a question like "who made the most tackles in the last 20 minutes of Premier League games in 2015/16?" and an AI writes the SQL, the page checks it, and your own browser runs it on 1,853 matches of real event data. The query is always shown, so every number can be checked.

The story

This replaces two earlier projects, a player churn pipeline and a SQL agent on top of it, with one thing people actually want to use. The data is StatsBomb's open event data: every tackle, shot, foul and card with the minute it happened, across four complete 2015/16 leagues, two World Cups, two Euros and Copa America 2024. Season totals for the 2024/25 top five leagues and MLS 2024 come from API-Football's free plan and fill in a little every day, inside its 100-request quota.

There is no database server. The site publishes the tables as parquet files, and DuckDB runs inside the visitor's browser, downloading only the parts of a file a query needs. The only server is a small Cloudflare Worker that keeps the Gemini key secret, rate-limits visitors, caches repeated questions and only ever returns one SELECT statement. Nothing sleeps, so the demo works the moment a recruiter clicks it.

What the evaluation found

The first run scored 18 of 19, and the miss was the dangerous kind: a confident wrong answer. Asked which team scored the most in Serie A 2015/16, the model ranked home goals and away goals as separate lists and reported Napoli's 49 home goals. I fixed the data model, not the question: a table with one row per team per match, so a team total never needs a home and away union. Roma's 83 is now the answer. The next run caught a cousin, grouping by the assist count itself, fixed with a rule that totals come from the pre-summed tables. The model is not fully deterministic even at temperature 0, so the evaluation reruns on every prompt or schema change.

Key decisions I'd defend in an interview

  • Checked twice before anything runs: the Worker and the page both reject anything but a single SELECT, block file, URL and settings functions, then EXPLAIN the query against the real tables. A failure goes back to the model once with the error; a second failure is shown, never papered over.
  • The data proves itself: every match's shots plus own goals must equal the official final score. That test caught StatsBomb naming "Olympique de Marseille" in one file and "Marseille" in another, which turned a 1-1 into a 1-0.
  • Honest xG: rules fixed before any result, every shot scored by a model that never saw its match (cross-validation grouped by match), and penalties given the observed 74.5% rather than modelled.
  • What was tested is what runs: one prompt and one schema file, bundled into the Worker and used by the evaluation. The schema guide is generated from the live database and the deploy fails if it is stale; the answer cache is keyed to the prompt version.
  • Free, within limits it states: the free data plan stops at 2024/25 and has no minute-by-minute data for it, so late-game questions about 2024/25 are declined rather than guessed.
